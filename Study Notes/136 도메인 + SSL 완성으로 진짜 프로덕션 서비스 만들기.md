## 📝 핵심 개념 요약

- *도메인(Domain)**은 사용자가 서비스를 인식하고 접근하기 위한 필수 요소
- **Route 53**은 AWS의 DNS 관리 서비스로, 도메인과 ALB를 연결
- *ACM(AWS Certificate Manager)**을 통해 SSL 인증서를 **무료 발급·자동 갱신**
- HTTPS 적용 시 **보안, 신뢰성, SEO** 모두 개선
- ALB에서 SSL을 종료하고 EC2는 HTTP만 처리하는 구조가 **운영 최적화 방식**

### 💻 실습 내용 정리

### 1️⃣ Route 53으로 도메인 연결

### ✔ 호스팅 영역 생성

- 도메인 구매 완료 가정
- Route 53 → **호스팅 영역 생성**
- 도메인명 그대로 입력

### ✔ 네임서버(NS) 설정

- Route 53에서 제공된 NS 레코드 확인
- 가비아 도메인 관리 페이지에 **NS 값 이전**
- `.com.` → `.com` 형태로 입력

### ✔ A 레코드 생성

- 레코드 유형: **A**
- 레코드 이름: `api` (서브도메인)
- **별칭 활성화**
- 대상: **Application Load Balancer**
- 리전: **ap-northeast-2 (서울)**

➡️ 브라우저 주소창에 도메인 입력 후 정상 접속 확인

⚠️ **미사용 호스팅 영역은 실습 후 삭제 (월 약 $0.5 발생 가능)**

---

### 2️⃣ ACM(SSL 인증서) 발급

### ✔ 인증서 요청

- Certificate Manager → 퍼블릭 인증서 요청
- 도메인:
    - Express API 도메인
    - Next.js 프론트 도메인
- **DNS 검증 방식 선택**

### ✔ 인증서 검증

- Route 53 자동 레코드 생성
- 평균 10~30분 내 발급 완료
- 상태: `발급됨` 확인

---

### 3️⃣ ALB에 HTTPS 적용

1. ALB → **리스너 및 규칙**
2. **리스너 추가**
    - 프로토콜: HTTPS
    - 포트: 443
3. **ACM 인증서 선택**
4. 기존 Target Group 연결
5. 브라우저에서 `https://도메인` 접속 확인 🔒

### ❗ 헷갈렸던 점 / 문제 해결:

### ❓ 왜 IP 주소에는 HTTPS 적용이 어려운가?

- SSL 인증서는 **도메인 소유권 기반**
- IP 주소는 인증서 발급 불가
- 👉 **HTTPS를 쓰려면 반드시 도메인이 필요**

### ❓ EC2에 직접 SSL 적용하지 않는 이유

- 인증서 갱신·관리 부담 증가
- 서버 스케일 시 설정 복잡
- 👉 **ALB에서 SSL 종료가 표준 아키텍처**

### ❓ ACM 인증서가 자동 갱신되지 않는 경우

- ALB 등 AWS 서비스에서 **실제 사용 중이 아닐 때**
- DNS 레코드가 변경·삭제된 경우

### 💡 느낀 점 / 배운 점:

- **도메인 + HTTPS 적용이 서비스의 ‘완성도’를 결정**
- 이제야 “실습용 서버”가 아니라 **실제 서비스 구조**라는 느낌을 받음
- ALB + Route 53 + ACM 조합이 **현업 표준 패턴**임을 체감
- 인프라는 단순 동작보다 **운영과 보안 관점이 더 중요**하다는 걸 이해함
