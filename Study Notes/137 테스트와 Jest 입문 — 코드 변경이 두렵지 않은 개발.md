## 📝 핵심 개념 요약

- *테스트(Test)**는 코드 변경 시 기존 기능이 깨지지 않았음을 자동으로 검증하는 장치
- 테스트가 있으면 **리팩토링·기능 추가·배포에 대한 심리적 안정감**이 생김
- 서비스 규모가 커질수록 **사람의 수동 테스트는 한계**가 있음
- 테스트는 단순 검증이 아니라 **코드의 동작을 설명하는 문서 역할**도 함
- **Jest**는 설정 부담이 적고, 유닛/통합 테스트를 모두 커버하는 JS 테스트 프레임워크

### 💻 실습 내용 정리

### 1️⃣ 테스트가 필요한 이유 이해

### ✔ 코드 변경 시 발생하는 문제

- 할인 기능 추가로 인한 기존 계산 로직 오류
- 로그인 기능 수정이 회원가입 로직에 영향
- 공통 함수 수정 → 예상치 못한 버그 발생

👉 **테스트 코드가 있었다면 배포 전 자동으로 감지 가능**

---

### 2️⃣ 테스트 코드 예시 이해

- 기본 동작 테스트
- 옵션(할인율) 테스트
- 엣지 케이스 테스트
- 기본값(default parameter) 처리

```tsx
functioncalculateTotal(price, quantity, discount = 0) {
return price * quantity * (1 - discount);
}
```

---

### 3️⃣ 테스트의 장단점 정리

### 장점

- 코드 변경 시 불안 감소
- 배포 안정성 향상
- 리팩토링 가능성 증가

### 단점

- 초기 개발 속도 저하
- 테스트 코드도 유지보수 대상
- 의미 없는 테스트는 오히려 비용

---

### 4️⃣ 테스트 작성 기준 정리

### 테스트가 필요한 경우

- 결제, 인증 등 **중요 비즈니스 로직**
- 여러 곳에서 사용하는 **공통 유틸 함수**
- 엣지 케이스가 많은 함수
- 레거시 코드 리팩토링
- 복잡한 알고리즘 / 정규식

### 테스트가 불필요한 경우

- 단순 UI 스타일
- 자주 바뀌는 마케팅 문구
- 외부 라이브러리 내부 구현

---

### 5️⃣ 테스트 종류 정리

| 테스트 종류 | 목적 | 특징 |
| --- | --- | --- |
| Unit Test | 함수 단위 검증 | 빠름, 독립적 |
| Integration Test | 모듈 간 연동 | 실제 DB/API 사용 |
| E2E Test | 사용자 시나리오 | 느리지만 가장 현실적 |

👉 **테스트 피라미드 권장 비율**

- Unit 70% / Integration 20% / E2E 10%

---

### 6️⃣ Jest 소개

- Meta(Facebook)에서 개발
- Zero Config 기반
- 직관적인 문법 (`describe / test / expect`)
- 빠른 실행 + Watch Mode 지원
- TypeScript와 궁합 좋음 (`ts-jest`)

---

### 7️⃣ Jest 실습 환경 구축

### ✔ 프로젝트 및 패키지 설치

```bash
mkdir jest-practice
cd jest-practice
npm init -y
npm i -D jest @types/jest ts-jest typescript
```

### ✔ 설정 파일 구성

- `tsconfig.json`
- `jest.config.js`
- `package.json` script 추가

```json
{
"scripts":{
"test":"jest",
"test:watch":"jest --watchAll"
}
}
```

### ❗ 헷갈렸던 점 / 문제 해결:

### ❓ 왜 모든 코드에 테스트를 안 쓰는가?

- 테스트도 유지보수 비용이 듦
- **중요도·변경 가능성·의존도 기준으로 선별**해야 함

### ❓ 테스트 파일 위치와 이름 규칙

- `.test.ts` 또는 `.spec.ts`
- Jest는 파일명 규칙과 폴더 구조로 테스트 자동 인식

### ❓ Jest 설정을 직접 해보는 이유

- 자동 생성은 편하지만 내부 동작 이해가 어려움
- 초기 학습 단계에서는 **직접 설정이 이해에 도움**

### 💡 느낀 점 / 배운 점:

- 테스트는 “귀찮은 작업”이 아니라 **미래의 나를 위한 안전장치**
- 코드 변경에 대한 두려움이 테스트로 줄어든다는 게 핵심
- Jest는 진입 장벽이 낮아 **백엔드 테스트 입문용으로 최적**
- 앞으로 API, DB 로직을 테스트로 보호해야겠다고 느꼈음
